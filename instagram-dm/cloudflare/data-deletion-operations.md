# データ削除依頼への運用対応

公開ページ /privacy.html と /data-deletion.html の連絡窓口はBUTAI公式LINE。運営者が依頼を受け付け、本人と対象投稿・コメントを確認して手動対応する。自動削除受付や期限付き自動消去は未実装。

1. 依頼者の本人確認と対象コメントID・投稿IDの特定を行う。処理履歴にはユーザー名と元コメント本文を保存していないので、Instagram上の対象コメントも確認する。
2. 管理画面で全体OFF、対象投稿OFFにする。既に送信中の呼び出しは取り消せないため、少なくとも60秒後に履歴とInstagramの配送結果を確認する。新たな送信待ちがない状態にする。
3. Cloudflare D1のコンソールで、本人確認済みのコメントIDを使いSELECTで対象行を確認した後、jobsの該当行をDELETEする。投稿全体や他人の行をまとめて削除しない。SQLには確認済み数字IDだけを利用し、LINEメッセージをSQLへそのまま貼らない。
4. jobs行を消すと重複防止の記録も消える。元コメントが残りWebhookが再通知された場合は再登録され得るため、対象投稿は停止したまま、元コメントの削除または再通知が処理対象にならないことを確認してから再開する。送信停止の継続希望がある場合は再開しない。
5. バックアップや外部サービスのデータは別管理であることを明示し、削除結果を依頼者へ連絡する。サービス終了時は認証を解除し、保存データの削除とCloudflare側の復元可能期間・保管設定を確認する。

照合例（123456は本人確認済みの対象コメントIDに置換）:

```sql
SELECT id, media_id, state, created FROM jobs WHERE id = '123456';
-- 対象が正しいことを確認した後に実行する
DELETE FROM jobs WHERE id = '123456';
SELECT id FROM jobs WHERE id = '123456';
```

運用で保持の必要性を定期的に見直し、不要な履歴を削除する。処理履歴の自動保持期限を導入した場合は公開ポリシーも更新する。
